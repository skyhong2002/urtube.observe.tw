# 私人觀看紀錄搜尋與翻頁

這輪依「個人洞察與觀看紀錄」方向，優先補上找回舊影片的能力。原本 History 只顯示指定期間最新 100 筆，無法搜尋或往前翻閱；現在可以瀏覽整份已匯入紀錄，預設每頁 50 筆。

## 使用方式與行為

- 在個人頁的「歷史」搜尋影片或頻道名稱，中英文皆可；文字為子字串搜尋，`%`、`_`、反斜線視為一般文字。搜尋文字最多 120 個 Unicode 字元。
- 預設最近 365 天，也可選 7／28／90 天或全部時間。指定開始或結束日期會取代期間快捷選項；起迄日皆包含，採台北時間。
- 「較早／較新」保留搜尋、日期與語言；重新搜尋或切換期間會清除舊分頁位置。可直接回到最新結果。
- 依日期分組，保留重看同片的各筆紀錄。來源只有日期時顯示「僅有日期」，不把儲存用的中午時間當作真實觀看時間；同一天的順序不代表真實觀看先後。
- 找不到結果或輸入錯誤時仍保留搜尋表單、清除篩選及可讀的提示。頁面支援繁中、英文、手機與桌面；保留原有擴充套件匯入控制。

## 隱私與權限

History 仍只開放本人登入或有效私人儀表板金鑰，公開個人頁和好友均不能讀取。授權先於篩選參數驗證；每次請求重新驗證權限。成功、錯誤與 History 轉址回應均不快取並禁止搜尋索引。

帶金鑰進入 History 時，先沿用既有機制換成 HttpOnly cookie，再轉到移除金鑰的網址。新的轉址只保留 History 篩選和語言，表單、分頁及語言連結不包含金鑰。分頁 cursor 只是位置，不能取代授權。

查詢使用參數綁定，影片標題與使用者輸入經 HTML 轉義，影片及縮圖 URL 排除可執行協定與內嵌帳密。這個功能不查詢、不解密 YouTube 私人搜尋紀錄。

## 實作邊界

History 直接查詢原始觀看事件及既有影片資訊，不執行整份儀表板統計、不載入外部分類、不啟動 AI 或補資料工作。沒有新增 API 金鑰、資料庫 migration 或索引。

分頁使用觀看時間加事件 ID，避免 offset 翻頁在新增最新紀錄時產生重複；每次取最多 51 筆，最多另作一次單筆存在性查詢。相同時間及重複觀看各自保留。cursor 與目前篩選條件綁定並有長度、型別與時間驗證。

這不是不可變快照：匯入、刪除、來源日期精度更新、影片資訊補齊，以及滾動期間推進，都可能改變結果。既有 cursor 若已無結果，可回到最新結果重新查詢。

## 驗證與效能

本機 `npm run check` 通過：426 項成功、0 失敗、0 略過；包含實際 Node → Python 數值服務整合測試。

新增 Repository、HTTP 權限及 HTML 輸出測試，涵蓋跨 100 筆、同時刻、重看、插入新紀錄、雙向翻頁、台北日期邊界、Unicode、萬用字元、安全轉義、金鑰與登入撤銷，以及 History 不重算儀表板。所有資料皆為記憶體或暫存合成資料。

瀏覽器實測：50 筆頁面、往前後翻頁、搜尋「音樂」、指定同一天、無結果、輸入過長、切換語言與手機版。900px／1280px 桌面及 390px 手機無水平溢出。

合成 25 萬筆紀錄、本機 Node 26／SQLite 3.53.4、暖機後五次中位數：

| 操作 | 耗時 |
| --- | ---: |
| 第一頁 50 筆 | 0.19 ms |
| 深處較早／較新頁面 | 0.25／0.24 ms |
| 命中約 1% 的影片／頻道文字 | 6.01／5.91 ms |
| 全期間完全無匹配 | 359.13 ms |
| 限定七日完全無匹配 | 11.89 ms |

這些是本機合成資料的查詢耗時，不代表正式環境 HTTP 延遲。既有時間索引支援分頁；任意子字串搜尋仍為線性掃描，且目前 SQLite 查詢同步執行。大型檔案中的無匹配搜尋會暫時佔用服務事件迴圈，後續應獨立評估中文適用的全文／三字元索引與搜尋資源隔離。
